## Task 3 – Метрики эксплуатации целевой архитектуры  

### 1. Панель KPI эксплуатации целевой архитектуры  

| Технический показатель (KPI) | Целевое значение метрики | Способ и инструмент замера (инструментарий / формула) | Бизнес‑смысл — какую проблему решает замер |
|------------------------------|--------------------------|--------------------------------------------------------|--------------------------------------------|
| **Доступность транзакционного ядра (API‑Gateway + микросервисы Orders, Warehouse, Delivery, Finance)** | ≥ 99.95 % в круглосуточном режиме (год) | Prometheus + Grafana: `availability = (sum(rate(http_requests_total{status=~"2..|3.."}[5m])) / sum(rate(http_requests_total[5m])) * 100` | Минимизация финансовых потерь и простоев при оформлении заказов, фиксации складских операций и выплат. |
| **Пропускная способность (Throughput) создания заказов** | ≤ 200 RPS (пиковый) при нагрузке до 500 000 отправлений/сутки | K6/Locust нагрузочное тестирование + метрика `http_requests_total{handler="order-create"}` в Prometheus; расчёт среднего RPS за 5‑минутный интервал. | Гарантирует способность поддержать 10‑кратный рост бизнеса без деградации отклика. |
| **Latency аналитики (DWH ← операционные события)** | ≤ 5 сек (от записи события в PostgreSQL до появления в ClickHouse) | End‑to‑end измеряется через `event_timestamp` (в CDC) и `ingest_timestamp` в ClickHouse; скрипт‑агрегатор в Grafana выводит `latency = ingest_timestamp - event_timestamp`. | Позволяет принимать оперативные решения (перепланирование, оптимизацию складов) в реальном времени. |
| **Устойчивость к пиковой нагрузке IoT‑потока** | ≤ 3 000 RPS записи координат без потери сообщений | Kafka + KSQL/Prometheus: `kafka_topic_partition_current_offset - kafka_topic_partition_log_start_offset` → расчёт задержки; `consumer_lag < 100` сообщений ≈ < 5 сек. | Обеспечивает полную трассировку грузов даже в часы пик, исключая «дырявые» данные о перемещениях. |
| **Консистентность EDI‑цепочки** | 0 % аномалий (например, INVOIC без подтверждённого DESADV) | Сервис‑контроллер в виде Saga‑координатора фиксирует состояние каждого документа; метрика `edi_consistency_errors_total`. | Исключает финансовые и юридические риски, связанные с неверными коммерческими документами. |
| **Скорость обработки платёжных веб‑хуков** | Потери ≤ 0 % (0 timeout, 0 failed ack) | Мониторинг `payment_webhook_success_total` / `payment_webhook_total` в Prometheus; alert при `failure_rate > 0.001 %`. | Гарантирует отсутствие «пропущенных» оплат, повышая доверие партнёров и конечных клиентов. |
| **Скорость доступа к профилю клиента (CRM‑контур)** | ≤ 50 мс (обезличенный UUID → профиль) | Grafana‑Dashboard измеряет `http_request_duration_seconds{handler="customer-profile"}`; округление до 95‑го перцентиля. | Обеспечивает мгновенный ответ в омниканальном клиентском сервисе, повышая NPS. |
| **Нагрузка на транзакционную БД (PostgreSQL)** | < 30 % CPU‑нагрузки, < 5 % IO‑wait в пиковые периоды | pg_stat_activity + pg_stat_io; агрегация `cpu_percent` и `io_wait_percent` в Grafana. | Позволяет монолиту оставаться стабильным до полной миграции; меньше риска отказов из‑за блокировок. |
| **Время отклика платежного виджета (frontend)** | ≤ 300 мс (первый байт) | Lighthouse / Web Vitals (`first-contentful-paint`) в CI; сбор метрик в Grafana. | Улучшает пользовательский опыт при предоплате и повышает конверсию покупок. |

### 2. Итоговый вывод для генерального директора Fast Cargo  

> **Переход к целевому состоянию позволит компании избежать финансовых потерь из‑за простоя транзакционной системы, юридических рисков несогласованных EDI‑операций и штрафов за нарушение ФЗ‑152 и PCI‑DSS.**  
> За счёт внедрения **событийно‑ориентированной микросервисной архитектуры, CDC‑pipeline (Debezium → Kafka → ClickHouse) и изоляции платёжного и персонального контуров** бизнес получит **доступность ядра ≥ 99.95 %**, **пропускную способность ≥ 200 RPS** и **анализ данных в реальном времени с латентностью ≤ 5 сек**, что полностью покрывает требования к масштабируемости (×10) и прозрачности.  
> Эти измеримые эффекты гарантируют окупаемость инвестиций в трансформацию уже в течение первых‑шести месяцев эксплуатации и обеспечат стабильную работу при росте нагрузки в десять раз, тем самым укрепляя позицию Fast Cargo как технологически готового партнёра крупнейшего ритейл‑холдинга «Продукты с душой».
